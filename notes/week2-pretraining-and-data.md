# 第 2 周：LLM 预训练、Scaling Laws 与数据整理

## 学习目标

本周围绕 decoder-only language model 的预训练流程，建立以下证据链：

1. 解释 next-token prediction 的监督信号来源。
2. 区分典型 LLM 预训练、普通监督学习与 in-context learning。
3. 解释 Tokenizer、context length 与训练 token 数的关系。
4. 说明模型规模、数据规模与计算量之间的约束。
5. 建立可评测的数据清洗、去重和候选生成流程。
6. 运行 tiny language model 的数据处理对照实验。
7. 运行固定模型与数据、改变训练计算量的 Scaling Laws 小实验。

## 1. Next-token prediction

设一条 token 序列为：

$$
x_1,x_2,\ldots,x_n
$$

其中 $x_i$ 表示序列中第 $i$ 个 token。

语言模型在位置 $t$ 使用前缀 $x_1,\ldots,x_{t-1}$ 预测 $x_t$。训练样本可通过原序列自动错位得到：

$$
\text{input}=[x_1,x_2,\ldots,x_{n-1}]
$$

$$
\text{target}=[x_2,x_3,\ldots,x_n]
$$

目标 token 来自原始文本本身，因此不需要人工逐 token 标注。这种训练方式属于自监督学习。

固定窗口长度为 $L$ 时，一个完整样本需要连续的 $L+1$ 个 token。前 $L$ 个 token 构成模型输入，后 $L$ 个 token 构成向右错开一位的标签。长度不超过 $L$ 的序列无法产生完整窗口，因为缺少最后一个真实 next-token 标签。

padding 只用于对齐 batch 中的 shape，不能冒充真实监督标签。若 padding 参与交叉熵，模型会被错误地训练为预测 padding；使用可变长度样本时应通过 loss mask 或 `ignore_index` 排除这些位置。

## 2. 预训练与普通监督学习

两者都会使用目标、损失函数、反向传播和优化器更新参数，不能按“是否存在标签”区分。

典型 LLM 预训练使用大规模原始文本，目标由文本自动构造，任务是学习广泛的语言分布。普通监督学习通常针对预先定义的具体任务，目标标签作为额外监督信息随输入提供。

预训练描述训练阶段与目的，自监督和监督学习描述监督信号的来源，两组概念并非完全互斥。

in-context learning 发生在推理阶段。模型利用 prompt 中的说明或示例完成任务，但不通过反向传播更新参数。

## 3. Tokenizer 与 context length

Tokenizer 先把原始文本切成 token，再用固定词表把 token 映射为整数 ID。模型接收 token ID，而不是直接接收字符串。

Tokenizer 本身不负责理解语义。词义和上下文关系由语言模型学习。

context length 按 token 数计算，而不是按字符数或单词数计算。不同 Tokenizer 可能把同一段原始文本切成不同数量的 token，因此会影响：

- 单次计算可见的原始内容范围；
- 训练数据量 $D$ 的统计；
- 训练计算量；
- 不同实验之间的可比性。

## 4. Decoder-only Transformer

tiny language model 使用 decoder-only Transformer。模型只接收当前 token 序列，不依赖独立编码器的 `memory`。

causal mask 会遮住当前位置之后的 token，防止训练时看到未来标签。若没有 causal mask，模型可以直接读取要预测的 token，造成标签泄漏。

## 5. Scaling Laws

用以下符号表示三个规模变量：

- $N$：模型参数量；
- $D$：训练 token 数；
- $C$：总训练计算量。

在模型结构和训练方式相近时，可以粗略写成：

$$
C\propto N\times D
$$

该关系是计算量的近似描述，不是精确 FLOPs 公式。

在固定计算预算下，单独增大模型通常会压缩可训练 token 数。模型过大而数据不足会造成训练不足，模型过小而数据很多则可能受到容量限制。计算最优分配是在固定预算下寻找合适的 $N$ 与 $D$ 组合，而不是把单个变量增到最大。

验证损失常用以下经验形式描述：

$$
L(x)=L_{\infty}+Ax^{-\alpha}
$$

其中 $x$ 是参数量、数据量或计算量之一，$L_{\infty}$ 是当前设置下的渐近损失下限，$A$ 与 $\alpha$ 是根据实验拟合的参数。

Scaling Laws 是经验规律，不是数学保证。模型结构、Tokenizer、数据分布或训练方法改变后，原有拟合参数和损失尺度可能不再适用。

### 实验结论必须匹配控制条件

- 固定训练 token 数、只改变参数量：研究模型规模变化，但计算量同时变化。
- 固定计算预算、联合改变参数量和数据量：研究计算最优分配。
- 固定模型和数据、只改变训练步数：研究同一模型增加训练计算后的变化。

这三类实验回答的问题不同，不能互相替代。

## 6. 数据整理流程

本项目使用以下顺序整理文本：

1. 规范化空白；
2. 过滤空文本；
3. 保持原顺序进行精确去重；
4. 执行最小长度等质量过滤；
5. 使用近似相似度生成待复核候选；
6. 通过人工金标准评估候选；
7. 人工复核或使用更强语义方法决定是否删除。

近似重复候选不是最终删除结果。高 Jaccard 相似度仍可能来自普通 token 重叠，低相似度也可能是语义相同但表面表达不同。

## 7. 候选生成指标

设 $U$ 为全部无序文本对，$C$ 为候选文本对，$G$ 为人工标注的真实重复文本对。

候选召回率为：

$$
\operatorname{Recall}=\frac{|C\cap G|}{|G|}
$$

候选精确率为：

$$
\operatorname{Precision}=\frac{|C\cap G|}{|C|}
$$

候选缩减率为：

$$
\operatorname{Reduction}=1-\frac{|C|}{|U|}
$$

候选缩减率只需要候选数量，候选召回率必须依赖覆盖全部评测文本对的人工金标准。只标注候选生成器已经返回的文本对，无法发现被预筛漏掉的真实重复对。

倒排索引先按 token 找到可能相关的文本，再只为共享有效 token 的文本生成预候选。过滤高频 token 可以减少比较量，但真实重复对若只共享被过滤 token，会在计算 Jaccard 前被漏掉。

## 8. Tiny language model 数据处理对照实验

实验脚本为 `tiny_lm_experiment.py`，输出为 `outputs/tiny_lm_comparison.json`。

两种训练数据方案为：

1. 规范化空白但保留重复文本；
2. 规范化空白并执行精确去重。

控制变量包括模型、Tokenizer、验证集、context length、batch size、训练步数和五个配对随机种子。唯一主动改变的变量是训练数据处理方法。

| 方案 | 平均验证 loss | 标准差 |
|---|---:|---:|
| 保留重复 | 3.1876 | 0.1457 |
| 精确去重 | 3.0575 | 0.1977 |

去重方案减去保留重复方案的配对平均差值为 `-0.1301`，配对差值标准差为 `0.0736`，五个种子上的胜率为 `100%`。

该结果只说明当前微型语料、模型和训练设置下，去重方案在五个配对种子中表现更好。语料极小，且种子 `22` 的差值约为 `-0.0014`，不能据此声称去重对所有语言模型都有稳定且明显的收益。

## 9. 训练计算量实验

实验脚本为 `scaling_law_experiment.py`，输出为 `outputs/scaling_law_results.json`。

实验固定模型、训练数据、Tokenizer、batch size、context length、验证集和五个随机种子，只改变训练步数。处理 token 数代理值为：

$$
\widehat{D}=S\times B\times L
$$

其中 $S$ 是训练步数，$B$ 是 batch size，$L$ 是 context length。该值表示模型处理的 token 数，不等于精确硬件 FLOPs。

| 训练步数 | 处理 token 数代理 | 平均验证 loss | 标准差 |
|---:|---:|---:|---:|
| 20 | 400 | 3.5481 | 0.0974 |
| 60 | 1200 | 3.0575 | 0.1977 |
| 120 | 2400 | 3.4376 | 0.2751 |

从 20 步增加到 60 步时，验证 loss 下降。继续训练到 120 步时，验证 loss 回升，说明固定小数据上的额外训练计算造成了过拟合。

## 10. 失败案例与结论边界

### 数据整理失败模式

- 假阳性：表面 token 高度重叠，但关键否定词、实体或关系不同。
- 假阴性：语义重复，但表面表达不同，token 集合重叠不足。
- 预筛漏检：真实重复对没有共享未被过滤的 token。
- 评测泄漏：同一文本或重复内容组同时进入调参与测试文本对。

### 训练实验失败模式

- 单个种子可能产生偶然结果，因此两种方案应使用相同种子进行配对比较。
- 胜率只反映方向一致性，仍需报告平均差值和差值标准差。
- 重复同一语料可以增加名义 token 数，但不会等比例增加独立信息。
- tiny corpus 上的生成文本只用于验证流程，不能作为语言质量结论。

## 12. 当前结论

本周已经形成从原始文本、Tokenizer、next-token 样本、decoder-only Transformer、训练与验证，到数据处理和 Scaling Laws 小实验的完整可运行流程。

当前实验支持以下有限结论：在本项目的微型语料和固定训练设置下，精确去重方案的平均验证 loss 更低；固定数据上增加训练步数先改善验证结果，继续增加则出现过拟合。

这些结果不能外推到真实大规模预训练。进一步验证需要更大且来源更丰富的数据、独立测试集、更多随机种子以及更接近实际训练的计算量统计。
